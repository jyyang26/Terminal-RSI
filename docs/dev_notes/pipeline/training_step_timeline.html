1全景时序图

五个阶段 A → E 在一个 step 内依次发生。唯一的例外是右上方虚线框： 下一个 step 的轨迹采集提前启动，与本 step 的模型更新在时间上完全重叠——这是整条流水线最重要的结构特征。

A 阶段主导 wall-clock

一条轨迹要在真实终端里跑最多 60 turn 并执行验证测试，耗时是分钟级到小时级。 采集通常比梯度计算更慢，这是 agentic RL 与传统 RLHF 最大的体感差异。

C 必须早于 D

Actor 的 advantage 依赖 baseline Vφ(st)， 而 Vφ 只能由 Critic 前向给出。逻辑依赖与显存约束在这里恰好同向，顺序无歧义。

E 是唯一的全局屏障

换权重前必须让在飞的采样收敛完毕，否则同一条轨迹的前后半段来自不同策略， 其 log πold 失去意义、ratio 不再可解释。

2五个阶段逐一展开

同样的五个阶段，换成「输入 → 做什么 → 输出」的视角再看一遍。

A轨迹采集 Rollout / Experience Collection主导耗时
  • 过采样（over-sampling）：目标 256 条轨迹，实际投放 280 条。终端任务的完成时间是重尾分布， 等最慢的那一条会让整个 step 停摆。
  • Agent–Environment 交互：每条轨迹是一个多轮 MDP。 每一 turn：策略读取当前观测（历史对话 + 上一条命令的输出）→ 产生动作（一条 shell 命令）→ 环境执行并返回新观测。上限 60 turn。
  • 上下文管理：长会话会超出模型上下文窗口，此时对历史做摘要压缩后继续， 而不是丢弃整条轨迹——否则长任务会被系统性地从训练分布里剔除。
  • 奖励：轨迹终止后在环境内运行该任务自带的验证测试，得到 r ∈ {0, 1}（可验证的结果奖励 / verifiable outcome reward），无过程奖励。
  • 截尾（tail cancellation）：先返回的 256 条被接受，其余在途轨迹直接放弃。 代价是批次分布偏向"快任务"，这是为吞吐主动接受的偏置。
IN ← 任务池中的 280 个 prompt
OUT → 256 条 (观测, 动作, log π_old, 终局奖励) 轨迹
B经验批次构建 Experience Batch ConstructionCPU 侧
  • 序列化 + loss mask：把多轮对话摊平成一条 token 序列，并逐 token 标注是否参与损失。 只有策略自己生成的 token 计入损失；环境回显的命令输出属于观测，必须屏蔽， 否则模型会去"学习拟合终端输出"。
  • 轨迹分组：一条轨迹可能因上下文压缩被切成多个片段，这些片段共享同一个轨迹标识。 它保证 (a) 同一轨迹不会被拆到不同优化 step；(b) 损失归一化时用整条轨迹的有效 token 数作分母， 而不是各片段各算一次。
  • 长度上限：超过训练上下文上限的样本按"先弃最早内容"裁剪，并同步裁剪 mask 与 log 概率，保持对齐。
  • DP 分片 + 微批装箱：按序列长度做负载均衡分区，使每个数据并行 rank 的 token 总量尽量相等， 并把微批数量对齐到并行度要求——否则流水线并行会失步（有 rank 空转等待）。
IN ← 256 条原始轨迹
OUT → 每个 DP rank 一份：token / mask / 奖励 / 分组 / 微批调度表
CCritic 更新 Value Function Update先行
  • 价值前向：对批次中每个 token 位置给出状态价值 Vφ(st)。
  • GAE：用 Vφ 把只存在于最后一个 token 上的稀疏奖励，反向递推成逐 token 的优势， 同时得到价值网络自己的回归目标 Rt。
  • 价值损失：带裁剪的平方误差，防止冷启动阶段单步跳变过大。
  • 为什么价值学习率远高于策略：价值头是随机初始化的新模块， 而策略是已经预训练好的。一个未校准的 Vφ 会输出错误的 advantage 符号， 直接污染策略更新方向。所以要让它尽快收敛——这也是前 2 个 step 只训 Critic 的原因。
  • 健康指标：explained variance = 1 − Var(R − V) / Var(R)。 由负转正才说明价值网络真的学到了信号，而不是在输出常数。
IN ← 经验批次
OUT → 更新后的 φ ＋ 交给 Actor 的 baseline Vφ(st)
DActor 更新 Policy Update后行
  • 旧策略前向：重新计算 log πold(at|st) 作为重要性比率的分母。刻意不复用推理引擎返回的 log 概率—— 训练与推理是两套不同实现，其数值存在系统性偏差，直接混用会给 ratio 注入与策略变化无关的噪声。
  • 构造优势：接收 Critic 的 baseline，得到每个 token 的 At，并做批内归一化。
  • clipped surrogate 反向：梯度在多个微批上累积后统一更新，等效于一个大 batch。
  • 约束方式：本配置只靠 clip 约束更新幅度，KL 惩罚项关闭（因此无需常驻一份参考模型， 省下可观显存）；熵不进入优化目标，但仍持续记录——熵崩塌是策略退化最早的征兆。
IN ← 经验批次 ＋ baseline Vφ
OUT → 更新后的策略参数 θ
E权重同步 Weight Synchronization全局屏障
  • 暂停采样：等在飞的推理请求收敛，避免一条轨迹跨两个策略版本。
  • 失效 KV cache：缓存里的 key/value 是旧权重算出来的，与新权重不兼容，必须整体丢弃。
  • 分桶广播：训练侧与推理侧的并行切分方式不同，权重需要先在训练侧聚合还原、 再按推理侧的布局分发。MoE 的专家参数量极大，必须分批传输而非一次性搬运。
  • 恢复采样：至此 πold ← πθ，off-policy 间隙被重置，进入下一 step。
IN ← 新策略参数 θ（训练侧布局）
OUT → 推理引擎持有新策略，可开始下一轮采样

3这个 step 里的 PPO 数学

只列出时序图中实际被计算的量，按它们被计算出来的先后顺序排列。

① 稀疏奖励 → per-token 奖励（阶段 C 开头）

rt = 0  (t < T)  ,   rT = r ∈ {0, 1} 奖励只存在于轨迹最后一个 token

一条数万 token 的轨迹，其奖励向量形如 [0, 0, …, 0, 1] 或全 0。 把这个极端稀疏的标量分配到每个 token 上，就是 Critic 存在的全部理由。 （若配置了 KL 惩罚，它会作为逐 token 的负奖励叠加进 rt；本配置该项为 0。）

② GAE：反向递推出逐 token 优势（阶段 C）

δt = rt + γ·Vφ(st+1) − Vφ(st) TD 残差
At = δt + γλ·At+1 从序列末端向前递推
Rt = At + Vφ(st) Critic 的回归目标
本配置取 γ = 1, λ = 1，代入后 At = r − Vφ(st)， 即 GAE 退化为 Monte-Carlo 优势：不做时间折扣、不做偏差-方差权衡， 完全由 Vφ 承担基线职责。对"要么全过要么全不过"的可验证任务而言这是自洽的—— 轨迹中途并不存在可供折扣的可信即时奖励。

③ 策略目标（阶段 D）

ρt = πθ(at|st) / πold(at|st)
LCLIP = −min( ρtAt,  clip(ρt, 1−ε, 1+ε)·At )
ε0.2，上下对称
KL 惩罚关闭 ⇒ 无需常驻参考模型
熵正则系数 0，仅作为监控量记录
clip 触发率关键监控项：持续偏高说明更新步长过大

④ 价值目标（阶段 C）

Vclip = Vold + clip(Vφ − Vold, −c, +c)
LV = max( (Vclip − Rt)², (Vφ − Rt)² )
c0.2
αφ : αθ15 : 1（价值头需从随机初始化快速追上）
warm-up前 2 个 step 只更新 φ，不动 θ
主指标explained variance 由负转正

为什么这个任务必须用 PPO 而不是 GRPO

GRPO 的基线来自组内对比
Ai = ( ri − mean(r1..n) ) / std(r1..n)

不需要价值网络，但前提是同一 prompt 采样 n 条才能构成有意义的组内基线。

这里的现实约束：n = 1

一条轨迹 = 一个隔离环境 + 最长数十分钟的交互 + 一次完整验证测试。 采样成本让 n > 1 不经济，而 n = 1 时组内均值等于自身，优势恒为 0—— GRPO 在这里根本无法提供梯度信号。 因此必须引入一个学习得到的价值基线，即 PPO。 代价是多训一个同规模网络，并因此触发显存共享与串行调度（阶段 C/D）。

4并行性：什么在重叠，什么必须串行

时序图上的相对位置不是随意排的。每一处「并行」和每一处「串行」都有明确的原因。

关系并行 / 串行原因
采集 step N+1 ↔ 训练 step N并行 环境交互是 CPU/IO 密集且在独立机器上，与训练 GPU 不争抢资源。这是把采集耗时"藏"起来的唯一手段。
280 条轨迹之间并行 各自独立的环境实例，无共享状态。并发度受环境创建速率与配额限制。
同一轨迹的各 turn串行 MDP 的本质：下一个观测依赖上一个动作的执行结果，无法提前。
Critic 更新 → Actor 更新串行 双重原因：① 逻辑上 Actor 的 advantage 需要 Critic 的 baseline；② 物理上两个同规模模型共享同一组 GPU，显存不允许共存。
DP rank 之间并行 各 rank 处理不同的样本分片，仅在梯度归约处同步。这也是为什么装箱必须按 token 数均衡——否则快的 rank 空等慢的。
PP stage 之间流水并行 微批在各级之间流动。要求所有 DP rank 的微批数量一致，否则流水线出现气泡甚至失步。
训练 step N → 权重同步串行 必须先有新权重才能广播。
权重同步 ↔ 采样互斥 同步期间暂停采样并失效 KV cache，保证任一轨迹只对应一个策略版本。
